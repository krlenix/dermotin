The old public HTML did not expose a Meta or TikTok pixel on the sampled home, product and FunnelKit checkout pages. The new RS Meta Pixel/CAPI setup is therefore an intentional addition, not a copied WordPress setting.

Tracking resolution is now based on the real request/browser hostname, not only the locale. Browser Meta/TikTok/Google scripts and server-side Meta CAPI therefore select the same site. Known production hosts are isolated: an unset `dermotin.co` value disables that integration instead of falling back to credentials used by `dermotin.rs`. The server derives the CAPI site from the trusted request host; it does not accept a site name from the JSON request body.

## Canonical and deployment finding

The current public Vercel deployment responds on both `dermotin.shop` and `dermotinshop.com`, while its generated sitemap advertises `dermotinshop.com`. The local project previously advertised `dermotin.shop`. The migration now treats `https://dermotin.rs` as the intended canonical origin, but the same values must be configured in Vercel before production cutover:

- `NEXT_PUBLIC_APP_URL=https://dermotin.rs`
- `NEXT_PUBLIC_DOMAIN=dermotin.rs`
- `NEXT_PUBLIC_CONTENT_LAST_MODIFIED=<actual ISO content update date>`
- the complete per-site tracking variables listed above

`dermotin.co` can remain a working ad hostname with identical paths while every page publishes a canonical URL on `dermotin.rs`. A later host-wide 301 can be introduced after ads and external links are updated.

## Source safety check
